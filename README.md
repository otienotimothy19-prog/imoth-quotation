# Imoth Insurance Brokers — Motor Quotation & Risk Note System

A full-stack replacement for the legacy single-page `imoth_motor_quotation.html`
tool (kept for reference under `legacy/`). Same insurers, classes, rates,
benefits, excesses and calculation formulas — now backed by PostgreSQL, a
FastAPI REST API, and a React client/admin split, with permanent quotation
and Risk Note records, server-side PDFs, email, and a full audit trail.

## Architecture

```
backend/    FastAPI + SQLAlchemy + Alembic + PostgreSQL
  app/
    models/       ORM models (users, clients, vehicles, insurers, motor
                   classes, rate bands/versions, quotations, quotation
                   items/snapshots, risk notes + status history, documents,
                   email logs, audit logs, system settings, numbering)
    schemas/      Pydantic request/response models
    api/routers/  REST endpoints (client-facing + /api/admin/* protected)
    services/     pricing_engine, rate_config, quote_service, pdf_service,
                   email_service, document_service, storage_service,
                   numbering_service, audit_service, settings_service
    seed/         insurers_data.py (legacy rate-card port) + seed_data.py
  alembic/        DB migrations
  tests/          pytest — legacy-parity tests + API smoke tests

frontend/   React (Vite) + React Router
  src/pages/client/   Landing, wizard (/quote), quotation view, accept
                       confirmation, documents
  src/pages/admin/    Login, dashboard, quotations, risk notes, insurers,
                       motor classes, rates, settings, users
```

## Why the calculation engine is trustworthy

`backend/app/services/pricing_engine.py` is a line-by-line port of the
legacy `computePremium` / `findBand` / `effectiveBand` JavaScript. To prove
it, `backend/tests/fixtures/parity_vectors.json` was generated by *actually
running* the original JS engine (extracted verbatim from the legacy HTML) in
Node across every insurer, every class, band-boundary and mid-band Sum
Insured values, every vehicle-age bracket, and every add-on combination —
**7,560 cases**. `pytest tests/test_pricing_parity.py` asserts the Python
engine matches every one to the cent. Run it after any change to the engine.

## Rate versioning & snapshots

Admin edits to rate bands (`Admin → Rates`) never touch historical data:

- Every save creates a new `RateVersion` row (full point-in-time config,
  audit-logged with the admin's reason).
- Every generated quotation stores its own complete, independent
  `QuotationSnapshot` (rates, insurer info, benefits/excess/limits, the exact
  calculation used) at generation time. Changing rates tomorrow cannot alter
  a quotation or Risk Note issued today.

## Local development

### Prerequisites
PostgreSQL 14+, Python 3.11+, Node 20+.

### Backend
```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # edit DATABASE_URL etc.
alembic upgrade head
python -m app.seed.seed_data     # seeds insurers/classes/rates + bootstrap admin
uvicorn app.main:app --reload    # http://localhost:8000, docs at /docs
```

### Frontend
```bash
cd frontend
npm install
npm run dev    # http://localhost:5173 — proxies /api and /files to :8000
```

### Tests
```bash
cd backend && source .venv/bin/activate
pytest                       # parity tests + API smoke tests (needs DATABASE_URL + seeded DB)
```

## Default admin login

Set via `BOOTSTRAP_ADMIN_EMAIL` / `BOOTSTRAP_ADMIN_PASSWORD` in `backend/.env`
before running the seed script (defaults to `admin@imoth.co.ke` /
`ChangeMe123!`). **Change this password immediately** via `Admin → Users`
after first login (or add a proper password-change endpoint before
production use).

## Security notes

- SMTP and database credentials live only in environment variables — never
  in the `system_settings` table or the API surface (`Admin → Settings`
  explicitly whitelists non-secret keys only).
- Admin APIs are protected by JWT bearer auth + role checks
  (`SUPER_ADMIN` / `ADMIN` / `STAFF`); there is no cookie-based session, so
  CSRF does not apply to this API.
- Client quotation/document endpoints are keyed by an unguessable UUID
  (the quotation ID) rather than requiring client accounts, matching the
  "no login for clients" UX goal. For a stronger guarantee, add an
  email-OTP step before `/quote/:id/accept` in a future iteration.
- Rate limiting via `slowapi` on login and quotation-mutating endpoints.
- All document storage uses server-generated filenames (no user-controlled
  paths); insurer logo uploads validate content-type and size.

## What's intentionally out of scope for this pass

- Client accounts/login (quotation links serve as the access token today).
- S3/cloud storage backend (the storage layer is abstracted in
  `storage_service.py` so swapping it in later touches one file).
- A dedicated password-reset/change-password flow for admin users beyond
  the existing `PATCH /api/admin/users/:id` (super-admin can reset any
  user's password there).

## Anonymous quotation downloads and email sharing

Comparison responses now include `offer_id`, `offer_token`, and `offer_expires_at` for each fully priced option. Offers reuse the existing `quote_selections` table and server pricing engine without creating a Client record. Apply migration `9b7c2e4a6d10` with `alembic upgrade head` before deploying: it adds `OFFERED` and corrects existing unselected offers. Download and email preserve `OFFERED`; only the secured select action changes it to `SELECTED_PENDING_DETAILS`. About You creates a `DOCUMENTS_PENDING` quotation, and all three documents plus explicit confirmation are required for `ACCEPTED`. Products missing mandatory tonnage must be prepared before their final price can be accepted.

Every priced insurer card orders its actions Download Quote, Share by Email, Accept This Quote, including on mobile. The pre-acceptance PDF and email state “Indicative Motor Insurance Quotation” and “This quotation has not yet been accepted and does not constitute an active insurance policy.” Sharing requires only a recipient email address and does not open About You or record an acceptance intention.

The new `/api/quote-offers/{offer_id}` endpoints require `Authorization: Bearer <offer_token>`:

- `GET /pdf` returns an attachment using the locked offer snapshot.
- `POST /email` accepts only `{ "email": "name@example.com" }` and requires a UUID `Idempotency-Key` header. Keep the key on network retries; use a new key only for an intentional new delivery attempt.
- `GET /api/quote-offers/{offer_id}` returns the quotation summary for the email return page.
- `POST /select` selects the existing snapshot and returns the existing Complete Acceptance response shape.

Set `PUBLIC_APP_URL` to the public frontend origin and configure the existing `SMTP_*` settings. The DigitalOcean app spec sets the production frontend URL. Email links keep their short-lived token in the URL fragment, which the return page removes after reading it. Every endpoint also checks the stored expiry and rejects access with another offer's token. Sharing is limited to five requests per IP per minute and five delivery reservations per offer, with database-serialized duplicate protection across workers. Attempts are recorded in `audit_logs` under `entity_type=quote_offer`, including recipient, status and request IP; raw SMTP exception text and access tokens are not logged. A worker interruption after reserving a send leaves it pending to prevent an unsafe automatic duplicate.
